# Knowledge-Journal-System-
a personal knowledge journal system system for organizing projects, technical documentation, workflow, and administrative knowledge 

With the internet being a loaded source to learn new information, specifically for me to learn how to program, how to analysis specific datasets and fields, and overall, how to diagnose coding issues and gather feedback to continue to improve your skills working with data, can get overwhelming when first starting off. The internet pre-AI was already a goldmine for information, through blogs, videos, Stack Overflow, and even more sources to get knowledge from. Now with AI, which can be seen as a self-teaching system that learns in masses through prompts, knowledge seems endless. 
With this rich load of information, I have made it a mission for myself to not get overwhelmed and to be grounded in my pursuit of knowledge. I believed in creating knowledge from the ground-up and understanding the foundation thoroughly before proceeding, and this is where I introduce my Knowledge Journal System (KJS). 
This system is pretty-straight forward. I simply create my own journal that helps me understand problems. I have a business journal, one that builds on my work on my reselling business, and a personal one, which is more curiosity and personal interest.
 The journal system became more then just to write notes but also write connections. The business journal “Vault” which is my own folder made using Obsidian which is a specific folder to write your journals in. From there, when writing my business journal system, I organized different workflows, projects, and area of responsibility into separate folders. This allows me to review specific scopes and diagnose problems more precisely. 
Most crucial, the KJS allows me to use personal knowledge for recalling information rather than using the internet, AI, textbooks, or knowledge from other people. When I encounter a problem, I first check whether I have previous documents of a similar situation. If so, my previous experience would guide me towards the solution. If I have not, I research the problem using external sources, which I then record that knowledge in my own words and examples 
Obsidian allows me to also create connections to multiple documents across different areas. For example, I would have a “project” folder, a folder that I would write out my programming projects I need and want to use for my business. Amid working on the project, I may need to learn specific Python libraries and how to use them that I did not establish yet. I would have a separate folder under “Python” as this is where knowledge of learning the programming language would go. From there, after documentation, can we create a connection from the project to the specific Python document. This allows technical knowledge learned in one context to become reusable across future projects. 

This is the core idea behind my approach to building knowledge from the ground up. Rather than repeatedly searching isolated answers from external sources, I gradually build personal knowledge through my own experimentation, trial and error, and deliberate feedback.
 
I also use Obsidian Canvas, a feature that allows me to create dashboards, tasks list, and remainders. This gives me a generalization of working to create deeper knowledge of specific scopes of responsibility. 

In short, the Knowledge Journal System allows me to engage in gathering enormous amounts of information online without being overwhelmed and dependent on the internet. Instead, I use knowledge gathered through external sources as an added layer of previous layers of knowledge build on from my own experiences, experiments, feedback, and reflections. Soon that knowledge gathered from external sources becomes personable, gathering wisdom and rinsing and repeating from there.
